# VOC：易用性（lane voc-usability，2026-10-22）

要支撑的决定：Rekey 下一步易用性投入先做哪几项（上手、Agent 集成、审批、团队/同步、价格叙事）。
放弃条件：若各平台合计独立作者 < 10 或无法区分“针对竞品”与“针对品类”，本 lane 只记 D1，不进入决策。
结论（待验证）：易用性痛点集中在**自托管装不起来**和**MITM 代理兼容性**，这两类 Rekey 在架构上避开了；Rekey 真正要补的是**Agent 侧接入（Claude Code / Codex 认证、技能文档、原生 CLI）**和**权限粒度/审批通道**。没有找到“审批太多”的原话，这一条只能算待验证。

## 4. 与上轮（10-06）的差异

- 上轮只采了 HN，集中在安全质疑。本轮增加了 GitHub issues，样本以实际使用者的报错为主，所以安装、兼容性、认证、OAuth 配置这几簇是新出现的。
- 上轮的安全质疑（“挡住 key 挡不住乱用”）本轮仍然大量出现（HN 47354790、47505294 等），但不计入易用性簇。

## 5. 局限

- Reddit 缺失，导致 Claude Code / Cursor 普通用户的声音偏少，样本偏向自托管的技术用户。
- GitHub issue 天然偏向报错，称赞几乎只来自 HN。
- 作者数是人工按簇归类得出的，存在 ±2 的误差。
