# v2.0.0-alpha.3 candidate — not released

Updated 2026-09-30. The latest completed public download remains alpha.2
(vault format v9). This note does not change Cargo versions, create a tag,
or claim that candidate features are in a downloadable archive.

## Candidate scope

The integrated source includes the Vault OSS interoperability work, protected
Agent onboarding and repair, local MCP stdio, external policy/approval signers,
origin-authenticated approval envelopes and Admin pending/get inbox, fixed
GitHub Actions JWKS, fixed Keycloak token exchange, and GitHub App comments.
It also includes the native macOS Admin client with remembered unlock, local
DEK/VRK rotation, explicit completed-execution audit pruning, metrics export,
bounded Anthropic text streaming, experimental macOS Seatbelt Agent launch,
and the two fixed Action-bound native plugin protocols added in PR #54.
Maturity and provider limits remain in the
[Feature Truth Matrix](../product-foundation/feature-truth-matrix.md).

The base includes PR #50's non-retryable uncertain GitHub exchange handling.
The subsequent #56 correction covers issued/revoked connector audit failures
after GitHub, Keycloak or Vault effects: `UPSTREAM_INDETERMINATE`,
`retryable=false`, CLI exit 8. Cleanup and durable terminal ordering remain
required even after the caller's audit deadline expires.

Vault format is v14. No in-place upgrade or old-format restore is supported,
including from development formats v10 through v13.
Keep alpha.2 binaries with alpha.2 backups; use an empty directory and recreate
Admin state for the new format. Default topology stays G1. Hosted approval,
enterprise identity, multi-tenancy, HA, private-network Vault and Windows
remain outside this candidate.

## Packaging work before a tag

The current archive workflow builds and installs `rekey`, `rekeyd`, and
`rekey-github-create-issue`. The last executable handles the two fixed native
plugin protocols; its filename does not imply arbitrary plugin support.
There is also a separate Developer ID signing and notarization job for
`Rekey.app`. Workflow configuration is not evidence of a published app.
It does not package `rekey-mcp`, `rekey-policy-sign`, `rekey-approval-sign`, or
the onboarding/repair/backup helpers. A release-prep change must explicitly
include the intended executables and their documentation, extend archive
inventory and fresh-install acceptance, and then update Cargo/Cargo.lock,
archive scope and Matrix membership together. Existing broker features such
as JWKS, Keycloak and approval inbox are compiled into `rekeyd`/`rekey` even
when helper binaries are absent; release notes must describe them.

## Gates

- Human security review of credential, signing and authorization changes.
- Integrated source tests, focused acceptance, security/fuzz/performance CI.
- Merge to main and successful checks on the resulting main commit.
- Release-prep packaging and archive acceptance for the selected tools.
- A version-matching tag reachable from main, two attested platform archives,
  native fresh installs and public-URL smoke.

No new provider or enterprise scope is needed to close these gates. These
fixes do not bump the package version or publish a new release.
