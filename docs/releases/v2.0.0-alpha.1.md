# Rekey v2.0.0-alpha.1

First public Alpha of the Rekey v2 local Credential Authority.

## Scope

- Fixed HTTPS Actions through short-lived capability tokens.
- Encrypted local SQLite vault with explicit lock/unlock and step-up proofs.
- Default-deny typed policy snapshots, encrypted backup/restore, launchd and
  systemd service definitions, and the closed GitHub App profile.
- Supported artifacts: macOS arm64 and Ubuntu 24.04 x86_64.

## Security boundary

The default deployment is G1: one trusted local user administering agents
under that same user. The Linux container/namespace G2 reference is separate,
bounded evidence and is not the default deployment. Rekey does not protect
against host root, kernel compromise, same-user process inspection, or direct
agent egress outside the documented G2 reference topology.

## Known limitations

- No v1 migration, Windows build, macOS G2 claim, arbitrary URL proxy,
  redirects, retries, SSE, streaming, dashboard, audit export, persistent
  policy, password replacement, general connector SDK, control plane, or HA.
- Response sealing detects raw, base64, base64url, percent-encoded and
  chunk-boundary reflections; it cannot detect every compressed, encrypted,
  derived, or application-specific encoding.
- Password attempt throttling and active policy/capability state reset when the
  broker process restarts. Complete valid database snapshot replay is not
  detected.

## Install and verify

Follow `docs/installation.md`. Verify `SHA256SUMS` and the GitHub artifact
attestation before extracting an archive.

## Upgrade and rollback

This Alpha has no in-place migration contract. Stop Rekey, preserve a verified
backup and receipt, replace only the two binaries, and run the documented
smoke checks. Roll back by restoring the previous binaries and the matching
pre-upgrade backup into an empty state directory. Never point an older binary
at state already opened by a newer incompatible version.
